# Kubernetes — CKA (Certified Kubernetes Administrator) Notes

Separate from `sessions/kubernetes/udemyBeginner/` — that folder covers the Beginner course (now finished through Services). This folder is for the CKA course, the actual prep target given the Qualcomm Kubernetes Platform Engineer friend-intel (see `../qualcomm_kubernetes_interview_prep_checklist.md` and the `project_qualcomm_k8s_platform_engineer_2026-10-09` memory).

**Supplemental reference:** [KodeKloud Notes — CKA Course Introduction](https://notes.kodekloud.com/docs/Certified-Kubernetes-Administrator-CKA/Introduction/Course-Introduction/page) — the official companion notes site for this exact course. Worth cross-checking against whenever a digested note here needs a second source or a quick refresher without rewatching a lecture.

## Lectures

1. [Cluster Architecture](01-cluster-architecture.md) — the control-ship/cargo-ship framing, master node components (etcd, kube-scheduler, Controllers, kube-apiserver), worker node components (kubelet, kube-proxy), and why every node needs a compatible container runtime. Heavy overlap with the Beginner course's own Lecture 02 — treat as a refresher pass, not new material.
2. [ETCD For Beginners](02-etcd-for-beginners.md) — what a key-value store is vs. relational/document stores, getting started with the etcd binary + `etcdctl`, and the v2-vs-v3 API/command-set history (`set`/`get`/`rm` → `put`/`get`/`delete`). Standalone etcd primer, not Kubernetes-specific — genuinely new depth beyond the Beginner course.
3. [ETCD in Kubernetes](03-etcd-in-kubernetes.md) — etcd as the single source of truth for all cluster state, the two deployment methods (from-scratch manual service vs. `kubeadm`'s static Pod in `kube-system`), the advertised client URL the `kube-apiserver` needs to reach it (with the actual YAML flags + diagram), exploring the `/registry` directory structure via `etcdctl`, and a preview of multi-instance HA setups.
4. [Kube-apiserver](04-kube-apiserver.md) — the central hub every request goes through, the full Pod-creation request flow (sequence diagram), confirmation that `kube-apiserver` is the *only* component that talks to etcd directly, `kubeadm` vs. from-scratch deployment, the `--etcd-servers` flag (matching etcd's `--advertise-client-urls`), and where to find its config either way.
5. [Kube Controller Manager](05-kube-controller-manager.md) — the "department" analogy for controllers, the Node Controller's concrete failure-detection timeline (5s check → 40s grace → +5min before rescheduling), all controllers bundled into one process, the `--controllers` enable/disable flag, and where to find its config.
6. [Kube Scheduler](06-kube-scheduler.md) — only decides *which node*, never creates the Pod itself (that's kubelet); the two-phase filtering + ranking process with a concrete CPU example.
7. [Kubelet](07-kubelet.md) — the per-node agent managing containers; the one real exception where `kubeadm` does *not* auto-install a component (must be installed manually on every worker node); the `--container-runtime-endpoint` flag tying back to the CRI/containerd lecture.
8. [Kube Proxy](08-kube-proxy.md) — confirms the Services/Pod-IP-instability problem already covered in the Beginner course, the actual mechanism (watches for Service creation, configures iptables rules redirecting Service IP → Pod IP), and automatic DaemonSet deployment via `kubeadm`.
9. [Pods](09-pods.md) — cross-referenced against the CKA notes site, confirmed no real differences from the Beginner-course coverage; full content merged here as the authoritative version.
10. [Replication Controllers and ReplicaSets](10-replicasets.md) — cross-referenced against the CKA notes site; one real difference folded in (`kubectl replace -f` is what CKA material uses, not `kubectl apply -f` — not fully interchangeable).
11. [Deployments](11-deployments.md) — cross-referenced against the CKA notes site; added a concrete worked `kubectl get all` example showing the Deployment → ReplicaSet → Pod naming chain.
